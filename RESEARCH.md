# Regression test selection references

Each patch starts from the same SQLGlot revision. That makes the expensive step reusable. Run the pinned tests once to record dependencies, then query the same evidence for every input patch. Selection can happen without importing the patched project or collecting pytest again. The following are design references. The selector and scheduler use original code.

| Reference | How it works | Application to this challenge |
| --- | --- | --- |
| [pytest-testmon](https://www.testmon.org/) and [its block algorithm](https://www.testmon.org/blog/determining-affected-tests/) | The first run records dependencies. Testmon associates executed source blocks with tests and compares checksums. Its example factors nested function bodies out of the enclosing block, leaving the definitions in the parent. Later pytest runs can deselect unaffected items. | A change within a function body can use narrower coverage than a change to its signature, defaults or decorators. Batch queries can use a single immutable baseline. |
| [pytest-rts](https://pypi.org/project/pytest-rts/) | A full baseline run with pytest-cov builds a per-test database. The plugin uses Git changes relative to that baseline to select pytest items in later runs. | Index baseline coverage by repository-relative path and old line. For independent supplied patches, query that index directly and emit the official test numbers. |
| [pytest-impacted](https://github.com/promptromp/pytest-impacted/blob/main/docs/usage.md) | Traverses the reverse import graph from changed modules. Package initializers, conftest scope and project configuration can widen the result. Its standalone CLI can report affected test files. | Import edges help with dependencies created during collection. Dynamic dispatch, dynamic imports and data reads can escape static import analysis. |
| [pytest-impact](https://github.com/az-pz/pytest-impact) | Resolves each collected item's fixture definitions, including overrides. Changed conftest hooks can affect an entire subtree. Computed fixture requests widen the candidate set. Its scope is the fixture graph. | Associate fixture consumers with the resolved definitions. Shared fixture setup may be executed under just one item's name. SQL data files require separate evidence of their readers. |
| [FineRTS, Liu et al., ISSTA 2023](https://www.cs.cornell.edu/~legunsen/pubs/LiuETAL23FineRTS.pdf) | Evaluates ways to distinguish edits that may affect a test from edits to unrelated members of a Java class. The paper evaluates extensions to the dynamic Ekstazi and static STARTS techniques. | Use a smaller unit only when the old and new program structure supports it. Python class construction and rebinding make several Java-specific arguments inapplicable. |
| [FineEkstazi](https://github.com/EngineeringSoftware/fine-ekstazi) | The Java/Maven implementation refines Ekstazi using Java semantics and finer-grained dependencies. Later researchers found omissions when added overloads changed which method a call resolved to. | An inserted Python override or registration can similarly change existing callers. Coverage of the new method is inherently unavailable in the old revision. [Follow-up evaluation](https://zbchen.github.io/files/ase2024.pdf) |
| [Hybrid regression test selection, Zhang et al., ASE 2024](https://zbchen.github.io/files/ase2024.pdf) | JcgEks combines dynamic file dependencies with a static method call graph and handles external callbacks. The authors used a separate checker to examine omissions. | Use fine evidence for local edits and widen for initialization, dispatch or unknown external behavior. Evaluate omissions independently from how many tests the selector saves. |
| [Datadog Test Impact Analysis](https://docs.datadoghq.com/tests/test_impact_analysis/how_it_works/) | Compares changes with prior passing runs using coverage and tracked files. Certain tests can be designated unskippable, including tests with external data dependencies. | A single locally collected baseline suffices for this input model. Preserve a full-suite fallback when dependency evidence is incomplete. [Python limitations](https://docs.datadoghq.com/tests/test_impact_analysis/setup/python/) |
| [pytest-cov contexts](https://pytest-cov.readthedocs.io/en/latest/contexts.html) and [Coverage.py contexts](https://coverage.readthedocs.io/en/latest/contexts.html) | pytest-cov associates a parametrized node ID and a setup, run or teardown phase with a line hit. Code executing before the first dynamic context is attributed to the empty context. | Merge phases by exact catalog node ID. Keep collection evidence separately. Group a failing subtest with its catalog parent as required by the scorer. |
| [Buildkite Test Engine](https://buildkite.com/docs/pipelines/speed-up-builds-with-bktec) | Uses historical test durations to distribute work across parallel jobs. Its planner also supports a maximum worker count and target duration. | Recorded catalog durations are the scoring weights. Compare schedules for one through eight workers using the actual two-second worker charge. [Planner flags](https://buildkite.com/docs/pipelines/configure/tests/bktec/installing-and-using-the-client) |

## Attribution

The next refinement also draws on [NameRTS: Names Are All You Need (2026)](https://arxiv.org/html/2605.25356v1), a Python approach that separates code elements and referenced names, combines static references with observed execution, and treats shared initialization separately. We adopt attribute-level dependency names and conservative initialization/lookup guards; we do not transplant its implementation or assume its reported safety transfers to this entry. The paper's cache and external-callback failure cases motivate retaining fallback contexts and independent mutation checks. [Developer implementation](https://github.com/ZJU-CTAG/NameRTS).

Our compiler-equivalence check is a limited application of FineRTS's distinction between computational and observable changes. It compares generated computation while retaining source and metadata observers; it does not apply Java-specific deletion or overload rules to Python. A proposed structural-method refinement remains disabled without complete negative-lookup evidence. Fresh construction alone also does not justify ignoring a changed copying flag: method dispatch, argument effects, and identity can remain observable.
